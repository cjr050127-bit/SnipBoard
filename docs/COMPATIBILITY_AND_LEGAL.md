# Snipaste 兼容性与法律风险说明

核查日期：2026-09-28。以下为基于 0.5.5 代码与公开条款的工程风险分析，不是律师出具的法律意见；主要按中国大陆场景讨论。

## 实际实现

- `discovery.py` 枚举进程并查询 Snipaste 可执行文件路径，读取相关注册表、快捷方式与常见目录。没有发现进程注入、内存读取或补丁功能。
- `source.py` 读取配置中的 `history_dir`，扫描图组目录的 PNG；读取 `.sp0` 中的未公开元数据，提取图组 ID 与名称候选；读取 `splog.txt` 的历史记录。`.sp2` 只检查存在，不完整解析；不导入 `.sp1`。
- `qt_app.py` 约每 5 秒检查已落盘来源；`catalog.py` 将图片复制到独立图库。源文件不被改写，SnipBoard 的整理关系不回写 Snipaste。
- 不分发 Snipaste 程序、图标、激活数据或用户真实截图。兼容结果不代表 Snipaste 官方支持。

## 风险判断

**定时读取用户有权访问的图片，并不因“监视”两个字就自动构成侵权；但只读也不是法律免责条件。**《计算机软件保护条例》第六条区分软件表达与思想、处理过程、操作方法，不能据此把全部功能相似认定为复制代码，也不能据此推断一切兼容实现合法。[条例](https://www.cac.gov.cn/2013-02/08/c_126468744.htm)

当前最应关注的是 `.sp0` 未公开格式的识别与解析。Snipaste 的 EULA 禁止修改、逆向工程、反编译、反汇编及再分发其软件。独立读取用户数据文件是否落入该条款，要看开发方式、条款效力、适用法律和实际证据；仅凭当前代码无法给出“肯定不侵权”的结论。只读本地 PNG 的兼容路径相对更直接，解析未公开元数据增加合同与争议风险。[官方 EULA](https://zh.snipaste.com/eula.html)

不要复制 Snipaste 或 PureRef 的代码、图标与受保护素材，不要宣传为官方插件或暗示授权。项目开源协议只能许可本项目有权许可的内容，不能授权第三方图片或 Snipaste 本身。

2025 年修订的反不正当竞争法对干扰其他产品正常运行、以不正当方式获取数据等设有限制。当前未发现破解或干扰功能；未来若增加绕过权限、破解保护、注入或大范围数据抓取，应重新评估。[现行法律](https://www.csrc.gov.cn/beijing/c105536/c7582544/content.shtml)

用户截图也可能包含他人作品、个人信息或商业秘密。本地整理与将图片公开发布是不同使用情形；来源可访问不等于有传播权。[个人信息保护法](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)

## 降低风险的方向

1. 保留独立产品名称与“非官方、无隶属关系”声明；用户自行从 Snipaste 官网获取并合法授权使用该软件。
2. 若要进一步降低兼容争议，可在后续版本提供只读取用户选择的 PNG 目录的模式，取消 `.sp0` 与日志解析，以用户自定义名称替代内部组名。此项是建议，0.5.5 尚未实施。
3. 在大规模推广或收费前，可向 Snipaste 作者申请书面兼容许可，或请软件知识产权律师审阅实现与协议。尚未联系作者，尚未取得官方授权。
4. 自愿赞助不是法律豁免。Snipaste 2.x 商业使用需要 Pro，SnipBoard 的许可与赞助不能替代 Snipaste 的授权；是否属于商业使用应按实际场景判断。
5. 同时履行 Qt/PySide6、Pillow、NumPy 等依赖的分发许可。提供源码不等于全部第三方许可义务自动完成。
