# 0.5.5：紧凑拼版重构

0.5.4 沿用的 18 像素间距在密集参考图中显得过宽；其评分又过于偏向所有图片面积相等，常选择有大块空洞的排列。本次同时调整默认间距和布局结构，目标是保持图片大小大致均衡，并减少结构性空洞。

## 操作

- 查看器调整窗口大小后按 Ctrl+P，或右键 → 紧凑排列，应用到当前集合全部图片。
- 默认图片间距为 3 个逻辑像素，窗口内边距也为 3 个逻辑像素。
- 右键 → 外观设置… 可分别调整紧凑排列与其他排列间距。紧凑间距可设 0 使图片相接，确认后立即重新排列。
- 新的间距偏好单独保存，升级已有图库会使用新的默认值；不会被原先的 `board.gap=18` 覆盖。
- 保留原图完整内容、比例与旋转角度；支持撤销与保存。已有布局不会在升级时自动重排。

## 算法与验证

参考 [Diorama 固定画布拼版](https://github.com/mendrik/diorama-2023) 中按图片长宽比逐层横向／纵向组合的思路，独立实现切分树布局。对树结构进行搜索，同时评价画布匹配程度与显示面积差异。两张图片还比较独立缩放的候选，避免横竖混合时强制齐边导致面积失衡或覆盖率倒退。固定间距参与几何计算，完整保留图片比例。未复制该项目代码、未增加运行依赖。

重排只依据图片比例、旋转后的外接框及实际图片面积占比，不受原始分辨率和之前手工调整的显示尺寸影响。斜向旋转的外接框内仍可能存在空白，这部分不计入有效图片覆盖率。

同时修复两项集成问题：首次打开当前工作组时重复加载取消初排；布局计算期间用户选择“适合窗口”或“实际大小”后，旧结果覆盖其视口操作。

## 可复现基准

基准使用合成矩形，未读取用户图片。覆盖率为完整图片面积除以可用窗口面积，不包含边距；同时比较旧版默认间距、新版默认间距，以及同为 3 像素的两版算法，区分缩小间距与算法变化的贡献。

| 场景 | 旧版默认 18 px | 旧版改用 3 px | 新版默认 3 px | 新版最大／最小面积 |
|---|---:|---:|---:|---:|
| 8 张横竖混合 | 69.7% | 82.0% | 98.1% | 1.96 倍 |
| 7 张全景与竖图 | 85.2% | 93.3% | 98.3% | 4.81 倍 |
| 13 张正方形 | 89.0% | 97.6% | 97.6% | 1.57 倍 |
| 竖向窗口，8 张 | 68.4% | 76.9% | 92.6% | 2.16 倍 |
| 宽窗口，8 张 | 71.1% | 77.8% | 98.0% | 3.77 倍 |
| 80 张混合 | 58.3% | 82.8% | 93.0% | 2.24 倍 |
| 240 张混合 | 47.1% | 84.2% | 88.4% | 4.74 倍 |
| 2 张横竖混合 | 66.7% | 68.7% | 68.7% | 1.00 倍 |
| 竖向窗口，2 张 | 69.8% | 72.0% | 72.0% | 1.48 倍 |

本机两张图计算约 0.7 毫秒，7–13 张约 0.38–0.46 秒，80 张约 0.69 秒，240 张约 0.88 秒。搜索预算为约 1.2 秒，受硬件和负载影响；限时搜索不保证全局最优，也不保证所有图片面积相等。复杂长宽比组合会以一定面积差异换取更少留白。

原始数据、合成对比图和原生窗口验收文件保存在开发目录 `docs/packing-0.5.5`。运行 `tools/benchmark_packing.py` 可复现；旧版实现保存在 `tools/_packing_baseline_0_5_4.py`。

## 验收状态

Windows 原生隐藏窗口验收通过：角落拖动旋转、移动／缩放窗口、紧凑排列视口边界、保存恢复、窗口层级与快捷键冲突检测，无 Qt 回调异常。本机屏幕实际 DPR 为 2.5；额外设置 Qt 缩放因子 2.5 后，实际 DPR 为 6.25，压力验收也通过。验收使用临时图库与合成图片，未进行真人桌面操作或跨显示器实测。
